Fixes and implementation decisions

  • Room replay now resets an Ended/Stopped native input with Stop before Play, waits for readiness, then applies the room revision. Previously Play alone could leave the player Ended indefinitely while time assignments looked like convergence.
  • The public smoke queue test now waits for both host and guest snapshots before indexing the host queue. Its earlier IndexOutOfRangeException was a test synchronization race. The final public run passes it and the remaining authorization/persistence checks.
  • Opt-in asynchronous JSONL diagnostics avoid disk work on native/UI callback threads. Collection includes native TimeChanged, sample state, revisions, seeks/settling, buffers, read latency/errors/cancellations, rates, clocks and dropped-event counts.
  • The retest driver calls existing controls without rewriting playback flow. Guest readiness gates the matrix. Unified guest logs and mode-specific frame folders preserve the evidence. The analyzer reports all matched samples, revision-steady samples, coverage and unpaired client outliers; it requires genuine paused/stopped states for paused seek checks.
  • The default policy retains raw native time, a 1,200 ms hard-seek threshold, a 100 ms rate deadband and ±3% correction. WATCHROOM_SYNC_EXPERIMENTAL=1 enables the tested tighter policy: bounded 500 ms interpolation, 600 ms seek threshold, 80 ms rate deadband and proportional ±5% correction. The tighter policy remains opt-in because the AVI test regressed. Native seek settling observes timeline advancement and has a two-second fallback.

What the measurements mean

Pairs use the nearest guest sample with the same playback revision within 150 ms of host server time. Guest samples may be reused; the public result includes 826 distinct guest samples and 97.85% host playing-sample coverage. The full public raw p95 is 421 ms; excluding the first three seconds of each revision gives 422 ms. Estimated, target-aligned p95 is 252 ms, but that is an estimator measurement, not a displayed-frame measurement. Twelve of 864 raw public pairs exceed 500 ms; none exceed 1,200 ms. No diagnostic drops, rate failures or non-cancellation range errors were recorded in that public run, and there were no disconnected samples. Guest read latency p95 was 63 ms, maximum 234 ms.

Two public native snapshot pairs show visible timecodes 53.800 vs 53.733 s and 113.600 vs 113.667 s: 67 ms apart in each pair. Snapshot requests differed by 26 and 58 ms. These are sparse native snapshots, not an operating-system presentation trace or proof of audio alignment.

The silent AVI reports native time roughly once per second and jumps ahead of the expected timeline. The tighter policy then repeatedly seeks back; host/guest made 39/38 corrective seeks, with 39/38 settling timeouts. There were zero rate-setting events in that run, so rate adjustment does not explain this observed loop. Guest reads had p95 141 ms and maximum 203 ms, with no non-cancellation range errors; the evidence does not support network read starvation as the primary cause.

AVI frame pixels also disagree with native position reports. At the first paired capture, the blue channel identifies frames near 103.100 s on the host and 103.000 s on the guest, while logged positions are 102.148 and 102.779 s. The frame pair differs by 100 ms, but position reports differ by 631 ms. Requests were 80 ms apart. Frame colors repeat every 12.8 s, so the frame indices are resolved using the known test phase. One host AVI snapshot was not written despite an accepted request. This small sample does not establish an AVI frame-sync p95; it establishes that native position is not a sufficiently trustworthy presentation-time proxy for this fixture.

Remaining issue and next investigation

The silent-AVI synchronization target remains unresolved. Determine whether VLC's reported time is a demux/decoder clock ahead of presentation, a video-only clock issue, or specific to this generated AVI, using displayed-frame timestamps over an extended capture sequence. Compare video-only H.264, H.264/AAC and representative AVI files under identical room conditions. A presentation-time estimator or confidence gate must be validated against that evidence before enabling tighter automatic seeks by default. Forced TURN, a broader codec corpus, continuous frame presentation and measured audio alignment remain unverified.
