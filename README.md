# Watchroom

A Windows desktop preview for watching local movies together. C# / WPF, LibVLCSharp, SQLite and native libdatachannel. Only the host needs the video file.

## Run the app

Open `artifacts/Watchroom/Watchroom.exe` after publishing, or build from source below. The self-contained publish includes the .NET runtime, libVLC, and app-local Microsoft Visual C++ x64 runtime dependencies; installing VLC or copying runtime DLLs separately is unnecessary.

1. On first launch, choose **Add my videos** to set up folders and scan your library, or **Join a friend** to enter an invitation. Only the host needs video files.
2. Browse the poster grid, open a series, then a season, then an episode. On Windows, selecting a movie or episode opens its own information page with artwork, metadata, and **Play locally** / **Watch together** actions. **Back to library** restores the same season, search, and filter.
3. Artwork and metadata are fetched automatically after scanning. Configurable providers try TMDB (with the bundled WatchRoom application key or an optional personal override), TVmaze, and Wikipedia in priority order. NFO files and locked fields take priority. Settings offer fill missing, refresh text, replace downloaded artwork, and retry missing artwork, plus language, refresh interval, and optional missing/upcoming episodes. Outstanding matching and artwork issues remain visible during retry cooldowns. Shows and seasons have stable identities; filename aliases in one show folder stay together, while same-name remakes stay separate. See [metadata and library behavior](METADATA.md) for numbering, duplicate versions, NFO support, and migration details.
4. For a room, configure a deployed HTTPS server in Settings and choose **Save changes**. Create the room, copy its invitation, and admit friends when they join. Settings drafts, including the TMDB key, apply when saved; **Cancel** restores saved preferences.
5. Host controls playback and room tracks by default; **Allow shared controls** permits guests to play, pause, seek and change tracks. Guests follow the host's audio and subtitle selections; volume remains personal. Buffering pauses everyone and resumes when participants report ready.
6. In a room, a guest's **Queues** page shows the host's saved queues. Guests can reorder and remove videos, create queues, and add the host's videos with **Add to queue** on a title in the host's library; the host applies each change to its own queues and shares the result with everyone. Only the host plays, renames and deletes queues. With **Browse my library** on (Watch rooms), one guest at a time browses the host's library and can start a title with **Play in room**.

In Windows **Settings → Playback**, choose audio and subtitle languages from the lists, then use the arrows to arrange their priority. Add subtitle rules for specific audio languages: for example, Japanese audio can prefer English, then Russian, then **Off**, while English audio uses **Off**. The default subtitle list applies to audio languages without a rule. Remove all languages from a list to keep the video's original defaults. Saved preferences apply to the next video, and manual subtitle choices last for that video. When a local file doesn't name a track's language (including Matroska tracks with no language tag, which players otherwise show as English), Watchroom identifies it offline with bundled models: Whisper tiny listens to audio from the first minutes, CLD3 reads text subtitles in Matroska and MP4 files, and Tesseract reads picture subtitles (Blu-ray PGS and DVD VobSub in Matroska) for CLD3 to name. Such tracks show *identifying language* for a few seconds, then the language found and *detected*; preferences wait for the result, which is remembered for the file. To skip that wait, identification starts early: when you open a video's page, which lists its audio and subtitles with their languages, and for the next episode or queued video while one plays. Subtitle files take the language their name ends with, as in `Movie.ru.srt` or `Movie.en.forced.srt`, or else the language of their text; this covers files loaded from the player, files shared in a room, and files beside the video that play automatically (those are named only when it's clear which track each file became). Untagged tracks that can't be identified, such as a sign track with a few words, show as *Unknown language* rather than the English players assume.

Library pages, posters, queue changes and start requests travel directly over WebRTC. The host's queues reach guests in chunks that stay under the room's message limit; a guest's change names the queue it was made against, so a change to a queue that has since changed is refused with a reason instead of landing on the wrong video. While a guest browses, the host sees where they are and keeps browsing their own library; **Follow** shows what the guest sees, and **Stop following** or scrolling returns to the host's own library. Browsing presence expires after connection loss, and the host can end a browsing session at any time.

Room playback uses a dedicated, reliable WebRTC control channel alongside the media channel. The host owns playback revisions, readiness and queue state, and guests synchronize to the host clock. Guest commands go to the host for authorization and distribution to every participant. Sites (or the local server) handles room registration, admission, signaling and discovery heartbeats; playback commands do not pass through it. Established peer playback continues if discovery becomes unavailable, but new joins require discovery. All participants must use the updated app; incompatible control channels time out with an update/rejoin message. A dropped host connection pauses guests, and the host must reopen the room before they rejoin.

Run `dotnet run --project tests/Watchroom.Smoke -c Release -- --direct-controls` from the repository root to test the actual Sites worker and native peer channels with two guests, blocked media reads, clock differences and a discovery outage (requires Node.js on PATH).

The app includes a default HTTPS room-service address. Its availability and public-network playback must be validated separately before release. An HTTP localhost address supports testing on this computer. See [server deployment](deploy/README.md).

The Windows **Home** tab opens with **Continue watching**, suggestions for unstarted movies, shows, and anime, and a **Mystery pick** from available titles. Continue watching resumes paused movies or opens the next unwatched episode of a started show. **Refresh picks** reshuffles suggestions and the mystery card. Guests see the same Home sections for the host's library and saved progress while the host permits library browsing; their playback starts in the room.

Local playback remembers your position and volume. Details offer **Resume** and **Start over**; **Return to player** in the sidebar keeps playback reachable while browsing. The player's queue menu includes an editable, persistent queue with episode labels, reordering, removal, and automatic advancement; with no queue loaded, it lists the playing show's episodes so you can jump to another. The room invitation appears in the top bar when connected to a room, and the bottom bar's **Participants** pill shows who is in the room.

In a room, choose **Voice** in the player's top bar or **Join** in the **Participants** menu to talk while you watch. Voice is optional per person: only people who join voice hear each other, the menu lists who is in voice, and an avatar ring lights up while someone talks. **V** mutes and unmutes your microphone (or, with push-to-talk on, sends your voice while held); the speaker icon on a participant's row mutes them just for you, and the slider beside it sets their level for you (up to 200%, remembered by name). The voice volume slider in the Participants menu applies as it moves. The movie fades to half volume while someone speaks. Settings › **Voice chat** chooses the microphone and output (Windows default follows device changes), shows a live microphone level, and controls microphone processing (Windows voice processing with echo cancellation, noise suppression and gain control, on by default so speakers playing the movie are not sent back to the room; Standard; or Raw), push-to-talk, sending the microphone continuously, auto-join, voice volume and lowering the video. Speech is detected in the voice band against the measured background with 100 ms of pre-roll and 600 ms of hold; listeners prebuffer 60 to 200 ms depending on measured arrival jitter. Joining tells the host at once while the devices open, and the panel shows which step a join is waiting on. Voice uses Opus at about 32 kbit/s over an unreliable, unordered WebRTC channel; guests send to the host, which relays each speaker to the others and enforces mute and a real-time rate limit. Hosts with older apps show "The host needs to update Watchroom to use voice chat." Run `dotnet run --project tests/Watchroom.Smoke -c Release -- --voice` for the codec, jitter buffer and live multi-guest room checks, and `dotnet run --project tests/Watchroom.DesktopChecks -c Release -- --voice-ui` / `-- --voice-devices` for the window and real audio device checks (device checks play at zero session volume).

Watchroom also opens videos like a regular player: the installer adds it to **Open with** and Windows **Default apps** for the video types it scans, and videos can be dropped on the window. A video the library knows (the same file, a copy with the same name and size, or another release of the same episode or movie) plays as that library title, with its progress, details page and next episode. Other videos play on their own and remember their position. Opening a video while Watchroom runs plays it in the open window.

Headset and keyboard media buttons can play or pause the current video, including while Watchroom is minimized or another app has focus. Windows media controls show the current title and playback state. Room playback buttons follow the host's shared-controls setting.

Search covers the whole library, including when browsing a season. Missing files have an **Unavailable** filter and disabled playback actions. A rescan recognizes a file moved or renamed within the library folders and keeps its watch progress, queue entries and metadata. **Correct title** works without a metadata token and survives rescanning. Folder categories can be edited in place; folder changes trigger scanning, and an active scan can be cancelled while keeping videos already indexed.

A folder with the **Music** category lists audio files (MP3, FLAC, M4A, AAC, Ogg, Opus, WAV, WMA, AIFF, APE, WavPack, MKA, Musepack) under **Music** in the sidebar, apart from the video library, and video folders keep listing only videos. To list audio files in **Mixed** folders as well, turn on **Mixed folders also list music** in **Folders**; it is off by default. Tracks are grouped into albums by folder, named from their tags, or from `Artist\Album\01 - Title` names when untagged, and use the album's `cover.jpg`/`folder.jpg` or embedded artwork. Disc folders such as `CD 2` join their album. Music never looks up film or show metadata and stays out of **All** and Home. While a song plays, the player shows its artwork, title, artist and album, keeps the controls on screen, lists the album's tracks, and plays the next track straight away. Songs always start from the beginning. Guests streaming a host's song see the same view.

Acquisition plugins can get missing and upcoming episodes, seasons and films. **Acquire** hands a plugin that supports the title's type (anime, show or movie) the video's name, the folder where it belongs and the library folders with their categories. See [acquisition plugins](PLUGINS.md).

## Build and test

Requires the .NET 10 SDK on Windows x64. This workspace has a local SDK in `.tools/dotnet`.

Publishing downloads and verifies Microsoft's signed Visual C++ runtime and restores a pinned WiX extraction tool into `.tools`. The payload hash is pinned in `scripts/copy-native-runtime.ps1`; if Microsoft's download changes, verify and update the hash deliberately. The extracted runtime is included in both portable and installer builds. `native-runtime.json` records its version and source.

```powershell
./build.ps1
./scripts/test.ps1
./build.ps1 -Publish
./scripts/package.ps1 -SkipPublish
```

Run the local coordination service with `./scripts/run-server.ps1`. Open two app instances using separate `WATCHROOM_DATA` directories to test host and guest independently. Tests generate their own media and never scan personal folders.

The smoke executable validates SQLite scans, byte ranges and authorization, real native WebRTC transfers, remote LibVLC AVI playback and seeking, room admission, host-only playback, automatic buffering recovery, and revocation. It starts a temporary loopback server and shuts it down afterward.

Desktop checks exercise media keyboard/app commands and room permissions with generated video. They run on a separate hidden Windows desktop so their windows never appear on yours; set `WATCHROOM_TEST_VISIBLE=1` to watch them. On an interactive Windows desktop, run `dotnet run --project tests/Watchroom.DesktopChecks -c Release -- --system-media-controls` to also verify play, pause, and toggle through the Windows media service while the test app is minimized.

## Playback diagnostics and VM retesting

Set `WATCHROOM_DIAGNOSTICS` to an isolated directory before starting the app to write `diagnostics.jsonl`. Logging is off by default and disk writes run off the UI/native callback threads. Events include playback revisions, raw and briefly interpolated positions, rate-setting results, seeks and settling completion, buffering, range-read latency, clock correction, and dropped-log counts. Separate directories are required for separate app instances.

The default synchronization policy retains the 1,200 ms seek threshold and ±3% rate correction. Set `WATCHROOM_SYNC_EXPERIMENTAL=1` to test the tighter policy: interpolate between VLC time events for at most 500 ms, use bounded proportional rate correction (0.95–1.05), and seek above 600 ms of per-client error. The tighter policy met the measured H.264/AAC public-room target but caused repeated corrections on the original silent AVI; it is therefore opt-in. Seek settling waits for native timeline advancement with a two-second fallback. Room replay resets an ended native input before starting it, then waits for native readiness before applying the revision. The measured fixture target is a pair-position p95 of at most 500 ms; this is not a guarantee for arbitrary peers, codecs, displayed frames or audio.

`scripts/playback-retest/prepare.py` creates isolated instrumented copies without changing playback control flow. Its test driver uses `WATCHROOM_TEST_MEDIA` on the host. The VM matrix waits for guest readiness, records both clients' unified logs, and requests native frame snapshots at shared server times. `run-matrix.ps1` takes a credential **file path** through `-PasswordFile`; do not commit credentials. To test the experimental policy, set `WATCHROOM_SYNC_EXPERIMENTAL=1` before launching the host and pass `-ExperimentalSync` to the matrix for the guest. `analyze.py` reports full and revision-steady distributions, client target errors, unpaired outliers, pairing coverage, native read/seek diagnostics and control assertions. Reports retain startup/transition results separately rather than discarding them.

Room AVI playback selects VLC's `avformat` demuxer because its native AVI demuxer exposes coarse read-ahead time over HTTP. The updated investigation and same-machine default/experimental retests are in [AVI-INVESTIGATION.md](AVI-INVESTIGATION.md). Host-to-VM validation of this change remains pending.

## Current implementation boundaries

- Original-file streaming and remote seeking work in automated same-machine tests. A Windows host/VM public-room H.264/AAC run met the experimental 500 ms p95 pair-position target. Silent AVI still fails that target; forced-TURN and wider multi-machine/media coverage remain unvalidated.
- External `.srt`, `.ass`, and `.ssa` sidecars matching the video filename are shared with the room. Embedded subtitles, audio tracks and fonts are delivered as part of the original file. Full HEVC/AV1/ASS/PGS compatibility still needs a representative media corpus.
- Videos are always streamed as the original file; Watchroom does not transcode or prepare smaller copies. Episode thumbnails are decoded with the bundled LibVLC when no episode image is available.
- Guest library browsing defaults off for each saved room. Library browsing reveals metadata/thumbnails; video bytes remain authorized only for the selected video and subtitles. Older clients retain their existing room controls without the guest library feature.
- HTTP room coordination retries transient network/server failures for up to 30 seconds using the existing session. Updated services deduplicate retried commands. Expired, revoked, or lost sessions still require leaving/rejoining and obtaining host approval. Host disconnect closes the room.
- The UI has dark/light themes. The shell uses software rendering for reliable WPF/native-video composition; libVLC retains hardware decoding.
- Windows update checks and a per-user GitHub installer are available; see [builds and updates](UPDATES.md). Publisher code-signing credentials are not configured.

These boundaries distinguish this working preview from the full release described in [the design plan](design-review.md).

## Data and privacy

Library/settings: `%LOCALAPPDATA%/Watchroom`, or `WATCHROOM_DATA` when set. On Windows, **Save changes** stores the TMDB key in Windows Credential Manager; clearing it and saving removes it. Poster searches send titles to TVmaze/Wikipedia, or TMDB when configured; movie files stay on the host. Disable automatic artwork in Settings to stop these lookups. The loopback media bridge uses an unguessable per-session path and serves authorized media IDs. Room signaling uses HTTPS/WebSockets; media uses WebRTC encryption, with TURN relay fallback when configured.

Room codes expire after six hours. Relay bandwidth and host upload increase with each viewer. A public server and a tested relay are necessary for dependable internet use.
